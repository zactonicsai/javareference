7. Jakarta Validation & Lombok Best Practices

In real applications, you should validate incoming data and reduce boilerplate code. This is where Jakarta Validation and Lombok come in.

Jakarta Validation (Request Validation)

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;

public record DocumentIngestionRequest(

    @NotBlank(message = "File name is required")
    String fileName,

    @Size(min = 5, max = 5000, message = "Content must be between 5 and 5000 chars")
    String content,

    String geoTag

) { }

This ensures invalid requests are rejected before reaching business logic.

Controller with Validation

@PostMapping("/ingest")
public DocumentIngestionResponse ingest(
    @Valid @RequestBody DocumentIngestionRequest request
) {
    return documentIngestionService.ingest(request);
}

@Valid triggers validation automatically.

Validation Error Handling

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Map<String, String> handleValidationErrors(
            MethodArgumentNotValidException ex) {

        Map<String, String> errors = new HashMap<>();

        ex.getBindingResult().getFieldErrors()
          .forEach(error ->
              errors.put(error.getField(), error.getDefaultMessage())
          );

        return errors;
    }
}

Lombok Builder Alternative

import lombok.Builder;
import lombok.Value;

@Value
@Builder
public class DocumentResponse {
    String documentId;
    String fileName;
    String status;
}

Lombok removes boilerplate and auto-generates builder code.

Manual Builder Interface

  • Full control
  • Custom validation logic
  • Enterprise consistency
  • Better for complex systems

Lombok Builder

  • Less code
  • Faster development
  • Easy to read
  • Best for simple DTOs

Best Practices

  • Use Jakarta Validation on all incoming requests
  • Keep validation out of controllers
  • Use Lombok for simple DTOs
  • Use Builder Interface for complex domain objects
  • Keep services responsible for business logic
